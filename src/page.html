How it works

  • Sensitive mode tunes 1 MHz of spectrum and splits it into narrow channels, each with its own pulse detector, so a weak signal only competes with the noise in its own channel. Two channel sets run side by side: fine channels (32 kHz) for ordinary sensors and wider, faster channels (64 kHz) that keep very short pulses sharp. The page keeps whichever copy of a transmission decodes best. In tests it decodes signals about 8 dB weaker than Classic mode or rtl_433 can. Signals that switch between two tones are detected and tagged FSK.
  • Signals that no decoder recognises are still turned into bits where the timing allows it (PWM, PPM, NRZ, Manchester) and logged as unknown. Repeated codes get their own device card. Packets whose timing looks random are discarded as noise.
  • Unknown signals are compared against a built-in device database extracted from rtl_433 (). Possible devices are ranked by modulation, timing and message length, and each links to its rtl_433 decoder. A match means "consistent with", not proof.
  • The IQ button on a log entry saves the raw radio recording of that packet (.cu8). Open it in Universal Radio Hacker, or run rtl_433 -A -r file.cu8. You can also send it to Claude to get a decoder written for it.
  • Regularity: each device's transmission times are tracked. Devices that send on a fixed interval (most weather sensors, every 30–90 s) get a green edge with the measured interval and the share of expected transmissions actually heard. They turn orange when one is overdue. Remotes and other on-demand devices are blue. The strip at the bottom of each card shows the last hour (newest on the right).
  • History (packets, device timing) is kept for the time you choose and capped at the disk size you set; older data is deleted automatically. Raw IQ recordings are kept in memory only (newest ~50 MB) and are lost when the page closes. Simulated packets aren't saved.
  • If you see a lot of junk, raise the trigger. To catch weaker signals, lower it to about 6 dB. Below that, noise starts getting through.

Setup

  1. Use Chrome or Edge. On Windows the dongle needs the WinUSB driver (installed with Zadig). If SDR++ works with it, it's already set up.
  2. Close SDR++ first. Only one program can open the dongle at a time.
  3. If Connect shows no device picker, serve the page from localhost: run python -m http.server in this file's folder and open http://localhost:8000.
  4. For weak signals, extend the antenna to about 17 cm, use gain 40–49, and put the dongle on a USB extension cable away from the PC.
